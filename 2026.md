> [!info] Périmètre
> Aucune slide n'a été modifiée. Ce rapport est purement descriptif : chaque constat est une
> case à cocher, à traiter ou à écarter. Les TD/TP sont hors dépôt : ce qui relève de la seule
> mise en pratique (faire démarrer un projet, `docker-compose`, config datasource) n'est pas
> compté comme un manque, sauf quand la notion elle-même manque à l'amphi.

## Résumé exécutif — les 12 points à traiter en premier

1. 🔴 **4 `src:` vers des fichiers supprimés** (`c2/logs.md`, `c2/actuators.md`,
   `c3/logs.md`, `c3/actuators.md`). Slidev les ignore sans warning → invisible.
   → [[2026/Structurel]]
2. 🟠 **`@Validated` sur un contrôleur est à retirer** depuis Spring Framework 6.1 : la
   validation des paramètres est désormais native et lève
   `HandlerMethodValidationException`. Tout le chapitre validation de c2 repose sur
   l'ancienne approche. → [[2026/Cours 2]]
3. 🟠 **`spring-boot-starter-web` → `spring-boot-starter-webmvc`**, et Jackson passe sous
   le groupId `tools.jackson`. → [[2026/Migration 4.1]]
4. 🔵 **Les proxies Spring en Kotlin ne sont jamais expliqués** : classes `final`,
   `kotlin("plugin.spring")`, auto-invocation silencieuse. C'est le piège n°1 sur
   `@Transactional` et `@Cacheable`, et les deux sont enseignés. → [[2026/Cours 3]]
5. 🔴 **`@Table("PonyTable")`** : `jakarta.persistence.@Table` n'a pas d'attribut `value`
   (4 occurrences). → [[2026/Cours 2]]
6. 🔴 **`@ManyToMany` inverse sans `mappedBy`** → une seconde table de jointure est créée
   (2 occurrences, dont le TL;DR). → [[2026/Cours 2]]
7. 🔴 **`@Configuration` au lieu de `@AutoConfiguration`** dans le chapitre
   auto-configuration, alors que c'est précisément le sujet de la slide. → [[2026/Cours 4]]
8. 🔴 **`@Container` sans `@JvmStatic`** dans un `companion object` → le conteneur
   Testcontainers ne démarre pas. Piège Kotlin classique, 3 occurrences. → [[2026/Cours 4]]
9. 🔴 **Deux exemples enseignent le mauvais ordre de règles** : `onStatus` WebClient qui
   avale le 404, et `authorizeHttpRequests` où `GET /**` permitAll tue la règle ADMIN.
   → [[2026/Cours 3]]
10. 🔴 **`@Test` manquant** sur les exemples MockMvc de c1 : le test ne s'exécute jamais.
    → [[2026/Cours 1]]
11. 🔵 **`ProblemDetail` / RFC 9457 absent** alors que `ResponseEntityExceptionHandler`
    est déjà utilisé : l'ajout est à coût quasi nul. → [[2026/Cours 2]]
12. 🟠 **RestTemplate présenté en premier et le plus longuement** alors que la doc Boot 4
    le qualifie de legacy et recommande RestClient. → [[2026/Cours 3]]

## §6 — Ordre et découpage des séances

### Ce qui est bien tel quel, à ne pas toucher

- **La progression globale** JEE → Spring → Spring Boot → DI → MVC → tests → validation →
  erreurs → config → JPA → transactions → clients → sécurité → production. Elle va du
  concret au transverse, chaque brique servant la suivante.
- **`c3/di-reminder.md`** en ouverture de c3 : 3 slides qui recollent DI +
  `@ConfigurationProperties` + JpaRepository en un seul schéma. Excellent point d'entrée
  après une semaine de coupure.
- **Filtres puis sécurité** dans c3 : Spring Security *est* une chaîne de filtres, l'ordre
  est le bon. → 🔵 il manque juste une phrase de transition explicite entre
  [[slides/pages/c3/filters|c3/filters.md]] et [[slides/pages/c3/security|c3/security.md]].
- **L'observabilité en fin de c4** avec la checklist Logs / Metrics / Telemetry qui se coche
  au fil des sections : bon dispositif de repérage.
- **c2/jpa2 conceptuel puis c3/jpa3 avec le DDL généré** : la double passe est pédagogiquement
  juste. Le problème n'est pas l'ordre mais la redondance du TL;DR (voir [[2026/Cours 2]]).

### Ce qui doit bouger

- [ ] 🟡 **Rééquilibrer c1 → c4.** c1 porte 89 slides, c4 seulement 64. Les coupes proposées
  dans [[2026/Cours 1]] (~12 slides) suffisent à aligner c1 sur les autres sans rien
  déplacer entre séances.
- [ ] 🟡 **`transactional.md:238-320` utilise Kafka** comme exemple de second
  `transactionManager`, alors que Kafka n'apparaît qu'en c4
  ([[slides/pages/c4/messaging|c4/messaging.md]]). Remplacer par un exemple déjà vu — deux
  datasources, ou un `TransactionTemplate` — et garder Kafka pour une remarque en c4.
- [ ] 🟡 **`test.md:611-648` (`@WebMvcTest`) mocke un `Repository`** alors que les
  repositories n'arrivent qu'en c2. Utiliser un `Service` : c'est aussi la couche qu'on mocke
  réellement sous un contrôleur.
- [ ] 🟡 **`c4/reactive.md` ne fait que 2 slides** pour WebFlux + R2DBC + coroutines +
  `async`. Soit l'assumer comme teaser et le dire, soit le porter à ~6 slides avec les
  threads virtuels comme alternative (voir [[2026/Cours 4]]). En l'état, le condensé produit
  du code qui ne compile pas.
- [ ] ⚪ **Ajouter une slide de conclusion.** Le cours s'arrête sur
  [[slides/pages/c4/telemetry|c4/telemetry.md:788]] = une image `/flam.avif` seule, sans
  texte ni récapitulatif ni pointeurs pour aller plus loin.
